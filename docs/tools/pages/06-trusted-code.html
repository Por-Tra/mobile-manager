Trusted person code

A code chosen by a close person. While it is set, every change that could loosen the restrictions requires it, and the settings screens that could disable Mobile Manager are closed.

What requires the code

Requires the codeStays free
  • Editing, deleting, enabling or disabling, reordering or creating a profile
  • Default rules
  • Zones and quotas
  • Detector editor (diagnostic mode)
  • Screen time goal of the dashboard
  • Debug test tools
  • Changing or removing the code
  • Starting a focus session
  • Activating or deactivating a profile by hand
  • Viewing everything (editors open read-only with an “Unlock” banner)

The check is done twice: the UI disables controls ({{rememberCanModify}}, {{LockBanner}}, {{UnlockDialog}}) and every ViewModel refuses the change ({{AppLock.canModifyNow}}).

Policy

  • 4 to 8 digits ({{LockPolicy.isValidPin}}).
  • A correct code unlocks for 5 minutes ({{LockPolicy.UNLOCK_DURATION}}).
  • 5 free attempts, then a 30 s wait that doubles at each failure, up to 1 hour ({{LockPolicy.lockoutFor}}). During a wait even the right code is refused ({{LockPolicy.attempt}}).
  • The unlock state lives in memory ({{AppLock}}): a restart of the process locks again.

Storage

The code is never stored in clear. {{PinHasher}} derives a PBKDF2-HMAC-SHA256 hash with a random 16-byte salt and compares in constant time. The iteration count is stored with the hash ({{LockConfig.iterations}}): 30,000 iterations take 0.67 s on a Galaxy A04s (120,000 took 2.7 s); hashes stored before the count existed are read as 120,000. DataStore keys: lock_pin_hash, lock_pin_salt, lock_pin_iterations, lock_failures, lock_locked_out_until ({{DataStoreLockRepository}}).

Protecting the app itself

While a code is set and the app is locked, protected Settings and installer screens (app info, accessibility, uninstall) are closed exactly as during a focus session, with the message “Protégé par le code du proche” ({{AppLock.protectsSettingsNow}}). Without that, “Force stop” would be enough: on the test phone, a force stop unbinds the accessibility service and Android does not bind it again until it is re-enabled.

Settings

Settings › “Code du proche” ({{LockSettingsScreen}}): set (entered twice), change, remove. The screen states that if the code is forgotten, only uninstalling the app resets it (all rules are then lost).

Note

The code is social friction, not a lock: safe mode, ADB or a reset get through. A 4–8 digit hash can be brute-forced offline by someone able to read the app’s data (root); the real protection is the attempt limit.
