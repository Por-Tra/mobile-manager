Focus sessions

A focus session (strict mode) blocks chosen apps until an end time. It cannot be stopped on a whim: ending it early requires a reflection delay chosen before the session starts.

Rules of a session

  • {{StrictSessionPolicy}}: duration up to 12 hours, reflection delay between 2 and 10 minutes, at least one app.
  • {{StrictSessionManager}} starts, overrides and closes sessions and writes the journal (STRICT_SESSION_STARTED, STRICT_SESSION_ENDED, STRICT_SESSION_OVERRIDDEN).
  • Start and end are stored as absolute instants in the strict_session table (which also keeps the history), so a session survives a reboot.
  • The running session is the top layer of the {{ProfileResolver}}: nothing below can allow a blocked app.

Ending early

  1. “Demander” starts the reflection delay; its start is stored, so the user may leave the screen.
  2. When the delay is over, “Mettre fin” is available for 2 minutes only; after that the request expires and must be started again. This prevents starting the delay at the beginning of the session to leave whenever one wants.
  3. Overriding ends the session (OVERRIDDEN). There is no other way to stop it from the app.

Foreground service

{{StrictSessionService}} (foreground service of type specialUse) shows “Fin à HH:MM · n apps en pause” with a countdown, closes the session automatically at its end (COMPLETED) and checks every 30 s that the accessibility service is active. If it is not, it logs PROTECTION_DISABLED, posts a high-priority notification and opens {{ProtectionAlertActivity}} when the overlay permission is granted. When restarted it reuses its last notification (otherwise the placeholder text overwrote it).

Restart safety: {{BootReceiver}} handles BOOT_COMPLETED and MY_PACKAGE_REPLACED; the home screen also restarts the service on every resume. System receivers obtain their dependencies through {{SessionEntryPoint}}.

Protected screens

During a session (and while the trusted person code locks the app), every Settings or package installer screen whose visible text contains “Mobile Manager” is closed with back and a short message ({{ProtectedScreenDetector}}). This covers the app info page, the accessibility page, device admin and uninstall. Side effect accepted: a list (apps, accessibility services) is closed too while the entry is visible. Detection relies on text, so a One UI update may require adjusting {{ProtectedScreenDetector.PROTECTED_PACKAGES}}.

Device administrator

{{MobileManagerAdminReceiver}} adds a message to the deactivation confirmation during a session and logs the deactivation. It does not prevent uninstallation; it adds a step. The real friction comes from protected screens.

Note

A determined user (safe mode, ADB, factory reset) will always get through. This is assumed: the session adds friction, it does not lock the phone.
