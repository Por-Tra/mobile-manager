Interface, languages and app updates

The persistent bottom navigation exposes Menu, Statistics, Profiles, Anti-scroll and Settings. The Menu shows current protection, focus sessions, daily usage, active profiles and enabled habits. Profiles provides direct creation, global rules and manual activation. Anti-scroll groups Reels/Shorts rules and habits (shared budget, opening pause and limit warning). Settings has Protection, Application and Advanced tabs. Editors and focus sessions keep their own navigation. Personal usage data stays on the device.

Visual design and access

The default theme is light with a lavender background, white rounded cards, purple actions, mint accents and calm apricot limit states. The vector phone-and-check logo is shared with the focus illustration. Theme tokens and typography live in ui/theme; reusable headers and feature cards live in ui/components/BrandComponents.kt. Dark tokens remain available for explicit theme use.

Main destinations preserve their state when switching tabs. The bottom bar scrolls when the screen width or font scale requires wider items, and brings the selected item into view. Statistics displays the graph before a compact weekly report, whose details can be expanded. Feature entry points take one to three taps from a main tab: Profiles > New or a profile; Anti-scroll > Reels/Shorts or Habits; Settings > Application or Advanced > an action. Scrolling, editing a form, selecting multiple apps, PIN checks, waiting periods and confirmation dialogs are additional interactions. Navigation never bypasses AppLock or strict-session protections.

Illustration and motion

Native Compose Canvas scenes provide layered phones, profile cards, paused-video cards, balance and shields, with gradients and shadows. Entrance animations stop after 700 ms, respect Compose duration scaling and do not run a permanent timer. Feature tiles respond to press. These drawings are decorative and do not independently assert protection status.

The usage ring uses real per-app usage shares and stays empty without usage. The three main apps show their actual integer percentages. Profile ribbons combine scheduled hours across selected days on a 24-hour axis; exact weekdays remain in the profile summary. Weekly bars animate actual durations, distinguish missing days and expose readable values to accessibility services. No rule, preference, permission or stored data is modified by these graphics.

Languages

Settings offers Phone language, Français and English. French is the default resource set, and English provides matching strings and plurals. Android 13 and later use LocaleManager; Android 10–12 use a persisted preference and localized activity contexts. Existing profile names are user data and are preserved.

Run python tools/check_resources.py to validate resource keys, plurals and printf arguments. Compose day labels observe the current configuration; time formatting follows the app locale.

Update flow

The user checks for updates, downloads the available APK, then opens the Android installer. Android may ask for permission to install unknown apps and for confirmation. Updating keeps app data; it does not require uninstalling the current app. Silent installation is not guaranteed.

The client requests the latest stable release from Por-Tra/mobile-manager. A release must have a semantic version tag and exactly one uploaded app-release.apk with a SHA-256 digest. APK downloads are size limited and restricted to HTTPS GitHub hosts. The package name, higher Android version code, digest and signing certificates are checked before installation. Drafts, prereleases and incompatible releases are refused.

Update actions are unavailable during strict sessions and while the trusted PIN is locked. Downloads belong to the Settings ViewModel and must be restarted if that screen is removed or the process dies.

Voluntary uninstallation

Settings > Advanced includes Uninstall the app and a farewell reminder that the user's time is precious. The action is unavailable during strict sessions and while editing is locked. It removes this app's active device administrator, if any, then opens Android's uninstall confirmation for this package only. Confirmation removes local profiles, settings and statistics. Cancelling preserves the app and its data, but the administrator remains disabled; the interface explains this before the action. Updating remains a separate flow and never requires uninstalling.

Distribution

The android-release.yml workflow builds and signs an APK when a GitHub Release is published. Configure the four signing secrets documented in UPDATES.md. Preserve the same signing key across versions. The client does not embed a GitHub access token and requires a publicly readable release.

Release codes use major × 1,000,000 + minor × 1,000 + patch. The current distribution version is 0.4.1, code 4001, including updates from local 0.4.0 test builds (code 4000). Publishing an update requires a higher version and code. Legacy releases such as the existing Beta debug APK are not offered by this distribution flow.
