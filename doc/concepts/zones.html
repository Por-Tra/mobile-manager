Zones and detectors

A zone is a part of an app — Instagram Reels, YouTube Shorts — that can be blocked or limited while the rest of the app (messages, posts, regular videos) stays usable. Instagram and YouTube are never modified: the accessibility service recognises the zone on screen, leaves it, and hides the button that leads to it.

Pipeline

  1. A window or content event arrives for an app that has detectors (ZoneEnforcer.onEvent). Bursts are grouped: a check runs 400 ms later, then every 800 ms and 1.2 s while the screen does not change (same zone, same nodes); any window change resets the interval to 400 ms.
  2. The screen is captured into a list of UiNode (identifier, text, description, selected, clickable, visible). AccessibilitySnapshot skips invisible nodes and their subtrees.
  3. ZoneMatcher.detect returns the first zone whose signals match (ZoneMatch).
  4. Time spent in the zone since the previous check is credited (ZoneUsageRecorder), then EnforcementCoordinator.evaluateZone asks the RuleEngine for a decision that includes that time.
  5. Allowed: the enforcer checks again within 5 s, or exactly when the quota runs out. Blocked: it runs one exit action (ZoneExitPlanner), shows a short message (“Reels masqués” or “Quota de Reels atteint pour aujourd’hui (50 min)”) and logs ZONE_REDIRECTED.
  6. In both cases the entry points of every inaccessible zone of the app are masked (EntryPointMask).

ZoneExitThrottle prevents loops: at most one exit action every 700 ms, and if the zone is still there after three exits, the regular block screen is shown instead.

Only visible nodes

Instagram keeps visited tabs in the accessibility tree, off screen. Reading the whole tree made the Reels player — invisible, behind the inbox — look present while the user was in their messages. Only nodes for which isVisibleToUser is true are considered (UiNode.visible); the matcher ignores invisible nodes even if a capture contains them. The diagnostic capture keeps them, greyed out as “hors écran (ignoré)”.

Targeted capture (fast path)

Each node read through the accessibility API is a round trip to the observed app, whose UI thread is busy while scrolling (about 40 ms of CPU and 500 ms of wall time per full capture on a Galaxy A04s). When every signal, hidden element and click target of an app uses an exact view identifier, ZoneMatcher.exactViewIds returns them and the enforcer asks the app for those identifiers only (findAccessibilityNodeInfosByViewId, see AccessibilitySnapshot.captureByIds). Instagram qualifies; YouTube does not (its Shorts tab is only recognisable by its label) and uses a full capture bounded to 800 visible nodes. Tests check that a targeted capture gives the same results as the whole tree on real captures.

Detector file format

Detectors are JSON so they can be repaired without a new build when an app changes its interface. The shipped file is app/src/main/assets/zone_detectors.json; a custom copy in the app’s private files (edited from the diagnostic mode) takes precedence when valid. Parsing and validation: ZoneDetectorParser.

FieldTypeMeaning
versionintMust be 1 (ZoneDetectorFile).
apps[].packagestringPackage name of the watched app (AppZones).
zones[].id, labelstringIdentifier used by rules (Zone(pkg, id)) and label shown to the user (ZoneDefinition).
anyOfsignal[]The zone is detected if at least one signal matches a visible node…
noneOfsignal[]…and none of these matches (avoids false positives, for example Stories).
exitaction[]Exit actions: the first applicable one on the first attempt, the next one if the zone is still there, the last one repeated. Back is the fallback.
hidesignal[]Entry points to mask while the zone is not accessible.
hideColor{light, dark}#RRGGBB colours of the mask, matching the app’s tab bar in the phone’s light and dark themes (MaskColor).

A signal (NodeSignal) lists conditions that must all hold on the same visible node:

ConditionMatches when
viewIdthe identifier equals the value, full (pkg:id/name) or short (name)
viewIdContainsthe identifier contains the value (prefer exact ids: they enable the fast path)
text, textContainsthe text equals / contains one of the values (case-insensitive, list for languages)
desc, descContainsthe content description equals / contains one of the values
selected, clickablethe node state equals the value

An exit action (ExitAction) defines exactly one of clickViewId, clickDesc, clickText or back. A click goes to the first clickable ancestor of the matching node.

Shipped detectors

JSON
{
  "package": "com.instagram.android",
  "zones": [{
    "id": "reels", "label": "Reels",
    "anyOf": [
      { "viewId": "clips_viewer_view_pager" },
      { "viewId": "root_clips_layout" },
      { "viewId": "clips_tab", "selected": true }
    ],
    "noneOf": [ { "viewId": "reel_viewer_root" } ],
    "exit": [ { "back": true }, { "clickViewId": "feed_tab" } ],
    "hide": [ { "viewId": "clips_tab" } ],
    "hideColor": { "light": "#FFFFFF", "dark": "#0C1014" }
  }]
}
  • Instagram Reels (verified on a real phone with Instagram 451): the Reels player and the selected Reels tab. Stories are called “reel” internally (reel_viewer_*), hence the noneOf. Back comes first so that a Reel opened from a conversation or from Explore returns where the user came from. The “selected” state is carried by clips_tab on the Reels screen (and by its child tab_icon elsewhere).
  • YouTube Shorts: reel_watch_fragment_root, reel_player_page_container, reel_recycler or the selected “Shorts” tab; exit through the Home tab, then back; the Shorts tab is hidden (desc “Shorts”, clickable). Never use viewIdContains: "reel": reel_time_bar also exists on regular videos.

Anonymised reference captures (identifiers and tab labels only) live in core/domain/src/test/resources/zones/; ZoneMatcherTest.kt checks the shipped file against them.

Masking entry points

While a zone is not accessible (blocked, or quota reached), EntryPointMask places a window of type TYPE_ACCESSIBILITY_OVERLAY — no extra permission — exactly over each hidden element. It has the colour of the tab bar (light or dark theme of the phone), leaves 2 dp at the top so YouTube’s divider line stays visible, and swallows taps: the button disappears and no longer reacts. This is the technique used by “Reels blocker” apps.

The mask follows the element at each check and is removed when the app leaves the foreground, when another window (the notification shade) becomes active, when the element is no longer visible (keyboard, full screen) or when the zone becomes accessible again. Zone decisions used for the mask are cached for 5 s.

The automatic exit stays as a safety net: a Reel reached another way (home feed, Explore, a Reel shared in a conversation) is still detected and left with back.

Diagnostic mode

Settings › Advanced › Diagnostic mode helps repairing a detector after an app update:

  1. Turn on the live overlay (DiagnosticOverlay): “App · zone: X (signal #N)” and a Capture button.
  2. Open the app, press Capture on the faulty screen (and on a screen that must not trigger).
  3. In the capture (HierarchyCapture), triggering nodes are highlighted; a long press copies a ready-to-paste JSON signal.
  4. Paste it in the editor (anyOf or noneOf), Check, Save, then confirm with the overlay.

Captures stay in memory (DiagnosticStore). Saving is locked during a focus session and without the trusted person code. The editor keyboard disables autocorrection (URI keyboard type: Gboard turned anyOf into any of).

Fragility

Note

Each Instagram or YouTube update may rename identifiers. Detection then stops (the zone and its button become visible again) until the detector is repaired with the diagnostic mode. If only clips_tab is renamed, the button is no longer masked but the automatic exit keeps working as long as the player is recognised.
