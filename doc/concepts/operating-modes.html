Operating modes

The user chooses the mode explicitly. Profiles, schedules and quotas remain user-configured; the app never switches modes automatically.

ModeBehaviour
FreeAll app and zone blocking, entry-point masks and protected-screen enforcement are disabled. Saved rules and local statistics remain available.
Semi-freeThe usual rules apply. Changing or disabling restrictions requires the trusted person code if set; otherwise an explicit waiting request.
RestrictedThe existing rule engine applies the saved profiles, schedules, quotas and strict sessions, with its usual code and session protections.

Explicit choice

AppMode is stored by ModeRepository in DataStore using its name. A missing choice, including after upgrading from a version without modes, leaves blocking disabled until the user confirms a mode on Home or Settings. Existing profiles and rules are preserved. Configure them and the trusted person code before confirming semi-free mode.

Requesting an unlock

In semi-free mode without a code, the user configures a minimum wait from 1 to 1,440 minutes (60 minutes proposed). The wait starts when Request unlocking is pressed. ModeUnlockManager persists the request timestamp, keeps the original start on repeated requests, and validates the current mode, code and strict session before granting access. Cancelling and requesting again starts a full new wait.

When the wait ends, blocking continues. The user must press Unlock, then can edit or disable the desired rules for five minutes. The request survives restarting the process; the five-minute editing window does not. Adding or removing a code or changing mode clears the request. A code, if set, always takes precedence over waiting.

Sessions and enforcement

Active strict sessions prevent mode changes and waiting-based unlocking. Their existing reflection and override flow remains separate. Free mode cannot start a new strict session. Manual profile activation, replacement and deactivation also require permission to edit, since replacing a policy layer could weaken blocking.

RuleEngine handles the free-mode gate centrally. Other modes preserve system whitelisting, layer precedence and explicit Allow semantics. The accessibility service observes mode settings and cancels stale checks, clears masks and recovers the foreground window whenever they change. No Room migration is needed.
